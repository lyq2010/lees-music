## 已定决策

- **技术栈**：Kotlin、Jetpack Compose、Media3 1.11.1（ExoPlayer + `MediaLibraryService`）。AGP 9.4.1、Gradle 9.6.0、Kotlin 2.3.21。AGP 9 自带 Kotlin，不要加 `kotlin-android` 插件。字节码目标 17（`compileOptions` 和 `jvmTarget` 都是 17）。
- **Material 3**：锁定 1.5.0-alpha29，不自动升级。稳定版 1.4.0 没有 `MaterialExpressiveTheme`、`ButtonGroup`、`WavyProgressIndicator`。alpha 以后改接口时要单独验证。进度条用细直线，不用占高度的波浪条。
- **JDK**：Android Studio 自带的 JBR（OpenJDK 25.0.3），路径 `D:\Android\Android Studio\jbr`。不依赖其他项目里的 JDK，不改全局 `JAVA_HOME`。
- **IDE**：Android Studio 2026.1.4.8（Quail 4 Patch 1），官方 zip，SHA-256 已按官方值校验过。支持 AGP 7.1 到 9.4。
- **服务端**：Navidrome 走 Subsonic / OpenSubsonic，兼容 Subsonic 1.16.1。认证是 token + salt（`t = md5(密码 + salt)`）。Navidrome 还不支持 `apiKeyAuthentication`；能力探测里以后出现这个扩展，再改用 API key。Emby、Plex 已列入服务器类型，接口未写。第一版浏览接口：`getArtists`、`getArtist`、`getAlbum`、`getAlbumList2`（最新、随机、最常播放、收藏）、`getPlaylists` / `getPlaylist`、`search3`。播放用 `stream`，`format=raw`。蓝牙媒体控制与曲库浏览是两件事；当前仅有媒体会话控制，曲库浏览需要实现 `MediaLibraryService` 回调，尚未开发。
- **数据**：第一版不上 Room。浏览用内存缓存加现有的本地 JSON。封面计划与 API 共用一个 OkHttp 客户端，用 Coil 3；这一步还没做。`security-crypto` 已废弃，不用。
- **地址**：一台服务器只存一个地址。主机栏前自动显示 `http://` 或 `https://`。内网明文 HTTP 用 network security config 允许 cleartext。不读 Wi-Fi SSID，因此不需要定位权限。计划初稿里的「内网地址 + 外网地址」两个输入框不再采用。网络变化、或暂停超过 5 分钟后再播放时，仍要对当前这一个地址：`connectionPool.evictAll()`，再探测，然后续传当前曲目剩下的部分。
- **密码**：Android Keystore 的 AES-GCM 加密后放进 DataStore。
- **点击和播放**：点歌曲先进播放页，不自动出声。顺序播放、随机播放、每日推荐右上角播放键，以及歌曲菜单明确标注的「立即播放」会出声。界面文案用中文，按能看懂的说法写，不把缓存、预取这些内部实现写到界面上。
- **界面**：`MaterialExpressiveTheme`。从当前专辑封面取种子色，用 Material Color Utilities 生成整套明暗色板，切歌时平滑过渡；没有封面时用品牌色。专辑封面从列表到详情、从迷你播放条到播放页，用共享元素转场，并尊重系统的「移除动画」。中文用系统 CJK 字体。标题的英文和数字另选展示字体，还没定，歌名暂用系统衬线。
- **播放页**：按官人给的参考图。圆角封面、歌名一行（右侧收藏和更多）、艺人 · 专辑、细进度条、控制行（随机、上一首、播放、下一首、歌词入口）、音量条、底栏（歌词、投屏、睡眠定时、循环）。投屏、睡眠定时、循环、收藏、更多还没接到功能。

- **ReplayGain**：读 OpenSubsonic 的 `replayGain`，曲目或专辑模式，自定义 `AudioProcessor`，加防削波。还没做。
- **无缝播放**：ExoPlayer 播放列表，加上预取下一首，切歌时下一首已经在本地。还没做。

## 防断连（核心机制已接入）

Symfonium 上的现象：锁屏或后台听一段时间后停止，或提示服务器离线；播到一半停住，或连续跳过好几首；暂停较久后再播放，要卡很久或失败。外网经过反向代理，没有开转码。

推测机制（还没有官人这边的日志或代理配置证实，依据是 Symfonium 论坛上的同类案例）：边播边下，缓冲区满了就停止读取，TCP 还开着但没有数据。反向代理的发送或读取超时（常见 30 到 60 秒），或锁屏后 Wi-Fi 省电，把闲置连接切断。缓冲区快用完再读时连接已死，重试失败就停住或跳到下一首。长暂停后恢复是同一件事：连接池里的旧连接已失效；NAS 硬盘休眠后，第一个字节也回来得慢。

三星 One UI 还有「休眠应用」和「深度休眠应用」，后台管控比原生 Android 激进，锁屏断连也可能来自这里。One UI 和 Android 的具体版本以真机为准。

对策：

- **整曲预取**：实际开始播放后，用 Media3 `CacheWriter` 在后台依次缓存当前曲和实际队列下一首，采用歌曲入队时选定的音质。播放走共享的 `CacheDataSource`；已完整缓存的曲目不再依赖服务器。默认上限 512 MB，可选 1 GB / 2 GB，按 LRU 淘汰；播放完保留，与离线下载分开。完成读取后归还连接，连接池可保留空闲连接，不承诺下载后立即断开 TCP。
- **断点续传**：下载中途断了，复用已写入缓存并用 `Range` 续读；临时网络故障按 1/2/4/8/16 秒退避，最多 5 次。416 回退完整 GET 并丢弃已读偏移之前的字节，不返回重复音频；不因连接失败主动跳歌。401/403/404 等不循环重试。
- **流连接只用 HTTP/1.1**：流媒体那个 OkHttp 客户端把 `protocols` 限定为 HTTP/1.1。API 请求不受这条约束。
- **超时**：连接 10 秒；读取 30 秒，给 NAS 硬盘唤醒留时间。
- **锁屏保持网络**：`ExoPlayer.Builder.setWakeMode(C.WAKE_MODE_NETWORK)`，播放期间持有 WakeLock 和 WifiLock。这句已经接上。
- **长暂停与网络变化**：暂停超过 5 分钟后再播放，停止旧加载、清理空闲连接池并重新 prepare，保留当前曲及位置。网络变化清理空闲连接并刷新预取；等待网络期间恢复连接可重试，主动暂停、停止或换队列取消旧恢复任务。没有额外的健康探测请求。

服务端可以一起查，可选，要官人提供反向代理类型和配置：代理的读取/发送超时、有没有开 HTTP/2、Navidrome 容器日志、UGOS 的硬盘休眠。
